## Build & Development Commands

### Development workflow
```bash
# Install dependencies
npm install

# Build the site (Eleventy compiles content/ to dist/)
npm run build

# Watch mode (auto-rebuild on changes)
npm run dev

# Run local dev server with Cloudflare Pages Functions
npx wrangler pages dev dist --ip 127.0.0.1 --port 8788
# OR use the npm script:
npm run serve
```

**Typical development setup:** Run `npm run dev` in one terminal to watch for changes, and `npm run serve` in another to serve the site with Functions at `http://127.0.0.1:8788`.

npm run lint          # Check for issues

## Architecture Overview

### Hybrid Static + Dynamic Site

This is a **mostly static HTML/CSS site** with dynamic data loaded client-side:
- **Eleventy (11ty)** is used only for blog/notes content generation
- The homepage (`index.html`) and core assets are passed through unchanged
- JavaScript modules in `scripts/` fetch live data from external APIs

### Performance Architecture

**Lazy Loading:**
- Intersection Observer with 50px rootMargin for smooth preloading
- Sections only fetch data when scrolled into view
- Reduces initial page load and API quota usage by ~75%

**Request Optimization:**
- Settings API call is deduplicated (single shared promise)
- Fetch utility with exponential backoff retry (1s, 2s, 4s)
- Automatic retry for 5xx errors, immediate return for 4xx
- Default 3 retry attempts per request

**Caching Strategy (Stale-While-Revalidate):**
- YouTube: 10min fresh, 1hr stale (`s-maxage=600, stale-while-revalidate=3600`)
- Books: 1 day fresh, 2 days stale (`s-maxage=86400, stale-while-revalidate=172800`)
- Strava: 30min fresh, 2hr stale (`s-maxage=1800, stale-while-revalidate=7200`)
- Serves stale content immediately while fetching fresh data in background

### Content Structure

**Static Homepage:**
- `index.html` - Main page structure with data attributes for dynamic sections
- `styles.css` - All site styles (single consolidated CSS file)
- `scripts/` - Vanilla JavaScript modules (ES6, no bundler)

**Blog & Notes (Generated by Eleventy):**
- `content/blog/*.md` - Markdown blog posts
- `content/notes/*.md` - Short-form notes (tweet-style)
- `content/_includes/layouts/` - Nunjucks templates
- Output: `/blog/YYYY/MM/slug/` and `/notes/YYYY/MM/slug/`

### Dynamic Data Architecture

The homepage displays live data from multiple APIs. This is orchestrated through:

1. **Lazy Loading with Intersection Observer** (`scripts/main.js`):
   - Sections are initialized only when scrolled into view
   - Each section has a data attribute (e.g., `data-strava-section`)
   - `main.js` observes sections and calls the appropriate init function

2. **Service-Specific Modules** (`scripts/*.js`):
   - `lastfm.js` - Now playing / recent tracks (uses iTunes Search for album art fallback)
   - `youtube.js` - Latest videos (decodes HTML entities in titles, duration badges)
   - `books.js` - Currently reading (Open Library for data, Google Books ALWAYS for covers)
   - `strava.js` - Recent workouts with mock data support

   **API Data Source Decisions:**
   - Last.fm provides music data; iTunes Search is fallback for album art
   - Open Library supplies book metadata; Google Books API used exclusively for cover images
   - Strava responses are sanitized server-side to strip all location/map fields for privacy

3. **Shared Utilities** (`scripts/utils/`):
   - `cards.js` - Card creation, skeleton/placeholder rendering (~200 lines of code deduplication)
   - `fetch.js` - Fetch with retry logic, exponential backoff, timestamp formatting

   **Card Component** (`createMediaCard()`):
   - Unified card generator for all media types
   - Supports: cover images/content, badges, titles, subtitles, custom content
   - Handles skeleton loading states and placeholders

   **Fetch Utility** (`fetchWithRetry()`):
   - Exponential backoff: 1s, 2s, 4s delays
   - Retries 5xx errors (server issues)
   - Immediately returns 4xx errors (client issues - don't retry)
   - Configurable retry count (default: 3)

4. **Cloudflare Pages Functions** (`functions/api/`):
   - `/api/youtube` - Proxies YouTube API (keeps API key server-side)
   - `/api/books` - Proxies Google Books API
   - `/api/strava/recent` - Fetches and sanitizes Strava activities (strips location/map data)
   - `/api/settings` - Exposes `LIVE_DATA_ENABLED` flag
   - All Functions use environment variables for API keys
   - Centralized validation via `functions/_shared/env-validation.js`

   **Environment Validation Pattern:**
   - All Functions use `validateEnv(env, ['REQUIRED_VAR'])` at start
   - Returns descriptive error messages listing missing variables
   - Prevents runtime errors from missing configuration

### Configuration System

**Client-side config** (`scripts/config.js`):
- Public usernames, channel IDs, limits
- NO API keys (those live in Cloudflare env vars)

**Environment variables** (Cloudflare Pages and `.dev.vars`):
- `YOUTUBE_API_KEY`
- `GOOGLE_BOOKS_API_KEY`
- `STRAVA_CLIENT_ID`, `STRAVA_CLIENT_SECRET`, `STRAVA_REFRESH_TOKEN`
- `LIVE_DATA_ENABLED` - Global kill switch for all APIs
- `STRAVA_ENABLED` - Strava-specific toggle

**Development mode** (`scripts/main.js`):
```javascript
const DEV_MODE = false; // Set to true for local dev without hitting APIs
```
- When `true`: disables all live API calls, uses mock data for Strava
- When `false`: normal production behavior
- **CRITICAL:** Always ensure `DEV_MODE = false` before committing to master

### Media Card System

All dynamic content (music, videos, books, workouts) uses a unified card structure:

**Standard card** (Last.fm, YouTube, Books):
- Cover area with image or badge
- Meta section with title and subtitle

**Workout cards** (Strava):
- Compact cover (8:1 aspect ratio) with workout type badge
- Meta section displays: large metric (time or distance), title, date
- Conditional logic: distance-based workouts show miles, time-based show duration
- Wider cards (`minmax(280px, 1fr)`) compared to other media (`minmax(160px, 1fr)`)

### Mock Data System (Strava)

For development without hitting Strava API:
- `MOCK_WORKOUTS` array in `scripts/strava.js` (6 diverse workout types)
- `useMockData` parameter in `initStrava()`
- Controlled by `DEV_MODE` flag in `scripts/main.js`

### CMS (Decap CMS)

Admin UI at `/admin/` for managing blog posts and notes:
- Uses GitHub OAuth for authentication (`functions/auth.js`, `functions/auth/callback.js`)
- Uploads media to `assets/uploads/`
- Writes markdown files to `content/blog/` and `content/notes/`

### Styling Approach

- Single `styles.css` file (no preprocessor)
- CSS custom properties for theming:
  - Supports `prefers-color-scheme: dark`
  - Variables: `--color-forest`, `--color-mint`, `--color-highlight`, etc.
- Responsive design:
  - Desktop: CSS grid with `auto-fit`
  - Mobile: Horizontal scroll with `scroll-snap-type`

### SEO & Accessibility

**Implemented Features:**
- Skip-to-main-content link (WCAG 2.1 Level A compliance)
- JSON-LD structured data (schema.org Person markup with social profiles)
- DNS prefetch for external APIs (Last.fm, iTunes, Google APIs)
- Noscript fallbacks with direct links to external profiles
- Semantic HTML and ARIA attributes where appropriate

## Key Patterns to Follow

### Adding a new dynamic section

1. Add HTML markup to `index.html`:
   ```html
   <section class="media-section" id="your-section" data-your-section>
     <ul class="media-row" data-your-list></ul>
     <p data-your-status>Loading...</p>
   </section>
   ```

2. Create `scripts/your-section.js`:
   - Export `initYourSection()` function
   - Use `createMediaCard()` from `scripts/utils/cards.js`
   - Handle loading states with `renderSkeleton()` and `renderPlaceholder()`

3. Register in `scripts/main.js`:
   ```javascript
   case "your-section":
     await initYourSection({ liveDataEnabled: settings.liveDataEnabled });
     break;
   ```

4. If using an API key, create a Pages Function in `functions/api/your-section.js`

### Working with media cards

Use `createMediaCard()` for consistency:
```javascript
createMediaCard({
  href: "https://...",
  coverUrl: "https://...", // or customCoverContent for custom elements
  coverClass: "media-card__cover--wide", // or --tall, --activity
  title: "Card title",
  subtitle: "Subtitle text",
  badge: "Optional badge text",
  additionalContent: customElement // for extra content in meta section
})
```

### Error Handling & Retry Pattern

All API fetches should use the retry pattern:
```javascript
import { fetchWithRetry } from "./utils/fetch.js";

const data = await fetchWithRetry('/api/endpoint');
```

**Retry behavior:**
- Automatically retries 5xx errors (server issues) with exponential backoff
- Does NOT retry 4xx errors (client/config issues - these need fixing)
- Displays retry button to users on persistent failures
- Shows timestamps and status messages for transparency

### Strava-specific patterns

Workout cards have special handling:
- Determine display metric: `hasDistance = activity.distance_m > 0`
- If distance > 0: show miles as main metric, time in subtitle
- If distance = 0: show time as main metric only
- Badge shows full workout type (e.g., "Weight Training", "Run")

## Important Notes

### Critical Rules
- **Never commit with `DEV_MODE = true`** - This breaks production by showing mock data
- **API keys must stay in Cloudflare env vars** - Never commit to `scripts/config.js`
- **Eleventy only processes `content/`** - Root assets are passed through unchanged
- **All scripts are ES6 modules** - No bundler, imports must use `.js` extension
- **Build before deploying** - Always run `npm run build` before testing with Wrangler

### Known Limitations & Context
- **API Quotas:** YouTube/Google Books quotas can block responses even with caching
- **Node Version:** Wrangler requires Node v20+ (check `engines` in package.json)
- **Work Page:** Intentionally removed after experimentation - don't recreate without discussion

### UX Patterns to Maintain
- **Timestamps:** All sections display "last updated" with relative formatting (e.g., "5m ago")
- **Retry Buttons:** Error states should include retry buttons for manual recovery
- **Loading Transitions:** Use opacity transitions on `.media-row.loading` for smooth updates
- **Status Messages:** Display clear, actionable error messages (distinguish config vs API failures)
